# Аква пати · CRM

Рабочее место администратора детского развлекательного центра «Аква пати».
Реализация макетов из `../project/Аква пати - Главный экран.dc.html` (30 экранов
на одном полотне) — React + TypeScript + Vite, дизайн-система OWLS.

Данные вымышленные и живут в памяти браузера: заказ можно создать, оплатить и
закрыть, деньги пройдут через кассу, смена закроется с пересчётом и отчётом.
Бэкенда нет.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # сборка в dist/
npm run typecheck
```

После входа открывается окно «Открыть смену» — смена стартует с остатком на

страницы не теряет смену; вкладка закрыта — данные сбрасываются к исходным.

## Правила расчёта

Всё считается из позиций заказа, ничего не захардкожено (`domain/rules.ts`):

- **Скидка клиента** — процент на весь заказ, округление до рубля в бо́льшую
  сторону при `.5`: 12 950 при 5 % → −648, 1 130 при 5 % → −57.
- **Разовая скидка** — плоская сумма на один заказ, поверх процента.
- **Доплата за время** — 350 за каждый начатый час сверх длительности тарифа.
  Фиксируется в момент оплаты: именно тогда записывается фактическое окончание.
- **Окончание** — фактическое, если визит закончился, иначе плановое
  (создание + длительность тарифа). **Прошло** — до фактического окончания, а
  пока ребёнок в зале — до планового.
- **Остаток** = позиции − скидки + доплата − возвраты − оплачено.
- **Цвет статуса**: зелёный — оплачен, жёлтый — не оплачен, красный — не
  оплачен и есть превышение времени (в исходных данных это заказ № 4795).
- **Баланс клиента** = перенесённый баланс − остатки по его открытым заказам.
  Положительный — предоплата, отрицательный — долг.
- **Выручка за смену** = наличные в кассе + безнал (определение с экранов
  «Касса» и «Закрытие смены»).

Скидки не суммируются — применяется наибольшая. Кафе, аниматоров, абонементов,
складского учёта и отдельных отчётов нет: всё это убрано по ходу проектирования.

## Устройство

```
src/
  domain/     types.ts · rules.ts (правила расчёта) · seed.ts (данные смены)
  state/      store.ts — состояние, производные срезы и действия
  components/ AppShell (меню и шапка) · Modal (формат А) · ui.tsx (поля, карточки, таблицы)
  screens/    по экрану на файл
  styles/     tokens.css и kit.css — дизайн-система OWLS как есть, app.css — слой продукта
  fonts/      Unbounded, Manrope, JetBrains Mono (кириллица + латиница)
```

`styles/tokens.css` и `styles/kit.css` перенесены из `_owls/` без правок, кроме
пути импорта и локальных шрифтов — цвета, типографика и компоненты берутся
оттуда через `var(--*)` и классы кита. Шрифты подключены локально, а не с
Google Fonts: касса должна отрисовываться без интернета.

Состояние — маленький внешний стор на `useSyncExternalStore`. Производные срезы
(журнал кассы, итоги смены, задолженность) считаются один раз на версию
состояния, поэтому снимки стабильны и перерисовки не зацикливаются.

```bash
npm run verify     # контрольные суммы смены + typecheck + сборка
```

  ok   Открытых заказов                        7

  ok   Наличные в кассе                   38 420
  ok   Безнал за смену                   102 920
  ok   Выручка (наличные + безнал)       141 340
  ok   Возвраты                            1 543
  ok   Инкассировано                      30 000
  ok   Задолженность                      13 802
  ok   Клиентов с долгом                       5

Таблица «Заказы» воспроизводит все 18 видимых строк полотна по времени,

`scripts/walkthrough.mjs` прогоняет все 30 экранов в браузере и складывает
скриншоты (нужен запущенный `vite preview` на :4173).

## Где данные разошлись с макетом

Макет местами сам себе противоречит — эти числа набирались руками. Там, где
выбор был, я считал показатель честно, а не подгонял:

- **Количество позиций справочника.** Экран 19 показывает праздничные программы
  и аквагрим как «Услуга», а экран 20 «Услуги · 7 позиций» их не содержит.
  Услуг стало 10, всего 33 позиции; счётчики во всех вкладках считаются от
  данных.
- **Число операций в журнале.** Макет заявляет «38 операций» при 42 заказах,
  из которых не оплачено 5 — то есть оплат уже минимум 37, плюс возвраты,
  внесение и инкассация. Счётчик считается от журнала.
- **Клиентов в базе.** Вместо «1 248 карточек» показывается фактическое число
  заведённых карточек (20).
- **Суммы отдельных заказов.** «Сумма» в списке считается из позиций заказа.
  Для заказа № 4810 вся цепочка совпадает с макетом до рубля (12 950 → −648 →
  −5 000 → 7 302), у остальных строк расхождение в единицы рублей: их суммы в
  макете не раскладываются на позиции каталога.
- **«Детей в зале».** Считаются дети по открытым заказам, чей визит ещё идёт.
- **Скидка у Мурадовой и Кузнецовой.** В списке заказов и в списке клиентов
  проценты разные; источником взята карточка клиента.
